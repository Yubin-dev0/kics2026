# N2 firmware on NUCLEO-F446RE

Bare-metal STM32CubeIDE project that wires `fw/core` to the HAL. All protocol, safety and
mode logic lives in `fw/core` and is unit-tested on the host; this folder adds only the
UART, DMA and DWT glue (`port/app_port.c`) and the project generated by STM32CubeMX.

The step-by-step Korean guide (A2 guide, Word) is the primary reference. This file keeps the
facts the build depends on.

## How the shared sources are compiled

`Core/Src/fw_sources.c` includes `fw/core/*.c` and `port/app_port.c` by relative path, and
`app_port.c` includes `../../core/app.h` the same way. The project therefore needs no linked
folders and no extra include paths. This matters because code generation from STM32CubeMX
(standalone since STM32CubeIDE 2.0) is reported to drop linked folders from the IDE project.
`main.c` includes the port as `#include "../../../port/app_port.h"`.

## CubeMX settings

| setting | value | why |
|---|---|---|
| board | NUCLEO-F446RE, peripherals in default mode | USART2 is already on PA2/PA3, the ST-LINK VCP pins |
| HCLK | 180 MHz, APB1 45 MHz | 921600 bps error -0.35% at 45 MHz; DWT tick 5.6 ns |
| USART2 | 921600, 8N1, oversampling 16 | PROTOCOL.md |
| DMA | USART2_RX, DMA1 Stream 5, Circular | idle-line reception without per-byte interrupts |
| NVIC | USART2 global interrupt enabled | idle and error events |
| init order | `MX_DMA_Init` before `MX_USART2_UART_Init` | otherwise DMA is never linked and nothing is received |
| toolchain | STM32CubeIDE, Generate Under Root checked | keeps the project root at `n2_safety/`, which the relative includes assume |

## Checks

- Smoke test: `python -m serial.tools.miniterm COMx 921600`, type `V*56`, expect
  `V,2,<date time> dbg,180000000*XX`.
- A2 run: `python fw\tools\a2_bench.py --port COMx --run N` (writes `data/a2/run_N.csv` and
  `run_N_meta.json`).
- Replay: `python fw\tools\replay_check.py --port COMx --out-json data\a2\replay_N.json data\a1\run_10.csv data\a1\run_11.csv data\a1\run_12.csv`

## Known constraints

- All recorded A2 runs use the Debug build configuration; the build id ends in `dbg` or `rel`,
  so the configuration is visible in every run's meta file. Switching configuration changes C.
- `HAL_UART_Transmit` is blocking (10 ms timeout). A worst-case C line takes 0.62 ms on the wire.
- UART errors abort DMA reception in this HAL; the error callback counts them in `bad_lines`
  and restarts reception.
- The line queue holds 4 lines. At 20 Hz with one reply per line it never fills.
